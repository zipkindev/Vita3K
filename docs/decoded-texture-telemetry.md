# Decoded-texture diagnostic telemetry

Set `VITA3K_DIAG_PVRTC_TELEMETRY` to a fresh CSV path before starting the emulator. The parent directory must exist. Unset it for normal operation. Existing paths are refused; verify the new file appears before testing. File/thread failures disable output without changing decode results. Output is diagnostic, private by default, and contains no texture bytes, hashes, guest addresses or game/save data.

A background writer takes one cumulative snapshot per second, flushing outside the cache lock. It writes an initial snapshot and a final snapshot on normal shutdown; abnormal termination can lose the final interval. The writer stops after 14,401 rows (about four hours at the default interval, bounded below 8 MiB). There is no event queue or per-texture file IO. Counters use the existing cache mutex; sampling takes a short additional lock, so overhead is small by design but not yet measured on the Go. Compare telemetry enabled/disabled on the same executable when measuring its impact.

`Qpc` and `QpcFrequency` on Windows share the raw counter used by ETW/PresentMon. `UnixNs` is wall time; `SteadyNs` is monotonic. Timestamps precede acquiring the snapshot lock; sampling and lock contention introduce jitter. Rows are coarse interval evidence, not exact individual decode events. Use surrounding QPC rows to calculate deltas and report their actual duration rather than assuming exactly one second.

Requests, hits, misses, bypasses, decodes and decode nanoseconds are cumulative. Decode timing covers the decoder call on misses/bypasses; it excludes hashing, copying cached pixels and insertion. With two-way decoding, it is elapsed caller time, not summed CPU time. DecodeGE2ms/10ms/50ms are inclusive, nested duration thresholds. MaxDecodeNs is the lifetime maximum. IntervalMaxDecodeNs and its width/height reset after each telemetry snapshot; a zero peak has zero dimensions. Counters can include loading, menus and multiple races.

Eviction causes are exclusive for each victim: ByteEvictions, EntryEvictions, BothEvictions, or ClearEvictions (a changed configured budget clears the cache). Their sum equals Evictions. ResidentBytes counts retained compressed and decoded vector capacities, excluding allocator/index metadata and transient allocations. A miss is not labelled as new versus previously evicted content; no unbounded texture-identity history is maintained. Evictions and misses in the same interval do not prove a particular hitch was caused by re-decoding.

For first-run versus warmed testing, restart the isolated emulator to empty decoded RAM, retain the same disk shader caches and settings, then record the first race and a repeat in that process. Label this a cold decoded-cache run, not a completely cold shader/system test. Keep event, class, ship, graphics, cache budget and decoder mode fixed, and annotate pauses/deaths/results. Preserve the working installation and production launcher mapping.

## Bounded preparation coverage (.21)

The Texture Cache Coverage Telemetry checkbox in Texture Decoding enables the existing counter CSV plus coverage tracking. It is off by default and restart-required. A fresh CSV gets a `.coverage-armed.json` activation report; on normal close, `.coverage-summary.json`, `.coverage-index.csv`, and `.coverage-decodes.csv` are written alongside it. Failed output does not change decoded pixels or cache policy.

The index retains at most 32,768 fingerprint candidates in a preallocated table, with at most 64 lookup probes. Slow decode detail (>=2 ms) is a rolling 8,192-record buffer. Summary counters cover every observed decode; capacity/probe drops and overwritten detail are explicit. Coverage payload is below 4 MiB in addition to the existing <=4 MiB reuse history; allocator metadata and stream buffers are additional. New records do no rendering-path disk IO, extra input hashing, or decoded-pixel retention. Telemetry overhead must still be measured.

Opaque IDs are session-local and connect decode detail to final index rows. Reasons distinguish absent launch-profile fingerprints, budget/deadline skips, not-prepared entries, prepared entries missed after eviction/clear, ambiguous registrations, and untracked observations. Fingerprint membership is diagnostic evidence, not proof of byte identity; the normal cache still compares exact compressed bytes before reusing pixels. Duplicate launch keys are marked ambiguous. Index rows include successful normal-close profile-save membership and learning eviction events. Historical learning evictions do not by themselves establish a performance problem.

`missQpc` is sampled on a cache miss; `endQpc` is sampled when the decode is recorded under the cache lock. This interval includes observer/lock overhead around the separately measured `decodeNs`. Use the shared Windows QPC frequency to correlate with PresentMon/ETW. Bypasses have untracked identity, even though their decode duration is counted.

A preparation status path also gets an immutable `.startup.json` snapshot. The original status path can still update on shutdown. For controlled tests, preserve a private immutable copy of the launch `learned.pvrp` before launch; this contains game-derived inputs and must never be included in public diagnostic uploads. No raw content hashes, texture bytes, guest addresses or asset names appear in the coverage files.
