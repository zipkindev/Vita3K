# Synchronization wait telemetry

Enable **Settings → Performance → Synchronization Wait Telemetry** before launching a game, or set `VITA3K_DIAG_SYNC_PROFILE` to a **new child directory** of an existing parent. UI output defaults to `cache/diagnostics/sync-waits/<unique session>`. Default off. Global and per-game settings use `sync-wait-telemetry`. Close normally to save; a crash may leave only armed.json. Reports are local and can contain process addresses and guest callsite identifiers; keep them private.

The recorder observes selected guest primitive waits (condition, mutex, semaphore, event, rwlock and event flag through handle_timeout), renderer queue/status/sync waits, Vulkan swapchain acquisition/present, selected GPU fence waits and frame-ready waits. These are elapsed API spans: wake-up/relock/bookkeeping and preemption can be included. Present includes driver work. They are **not pure OS sleep time, GPU execution time, mutex ownership proof or an exhaustive list of all blocking operations**. Spans on the same or different threads can overlap; never sum them as critical-path time. Kernel object IDs and related fields describe existing primitive/owner-or-associated-object snapshots. Guest import NID/LR and PC are diagnostic context, not replayable code or proof of a waker.

The disabled path checks one atomic flag and does not query clocks or native thread IDs. When enabled, scopes retain a shared owner safely across shutdown. A private **try-lock** at span completion protects bounded records and summaries: contention drops a record instead of blocking on the telemetry mutex. Publication/shared ownership uses standard atomic shared-pointer operations, which are not guaranteed lock-free. There is no span-path allocation or file I/O; buffers are allocated before main guest execution. This is lightweight instrumentation, not zero overhead, and needs an enabled/disabled comparison before attributing marginal differences to performance.

Payload limits: 65,536 × 80-byte rolling records (5 MiB), eight kind summaries and 4,096 × 56-byte session buckets (224 KiB). All accepted completed spans enter kind/session summaries; only spans of at least 2 ms enter detail. Buckets start at one second and fold adjacent pairs/double width as needed, with counts, elapsed sum/max and 2/10/50 ms counts preserved. Spans belong to their completion bucket; use retained detail for exact QPC intersection with a frame gap. Memory and output per session are bounded; the UI does not automatically delete old diagnostic sessions.

`armed.json`: QPC clock/frequency, bounds, schema, kind map and scope. `waits.csv`: chronological retained detail with native TID for ETW correlation, guest identifiers, object/context, API timeout budget (-1 if no finite budget known), raw result and result-known flag. Unknown result can indicate an exception; result interpretation differs by kind. `session.csv`: adaptive lifetime summaries. `kinds.csv`: per-kind lifetime totals. `summary.json`: accepted/detailed/retained/overwritten counts, try-lock contention drops, in-flight spans at stop, clock bounds and summary width. Detail can be incomplete due to its threshold, overwrite, drops or outstanding spans; check those fields before concluding that an absent wait did not occur. Export begins after guest/render/GPU-request shutdown and does not change wait conditions, scheduler policy or graphics behavior.

Other controls: `jit-compile-telemetry` enables the existing main-thread/x64 JIT observer; `decoded-texture-telemetry` enables one-second cache counters; `parallel-texture-decode` defaults true and selects caller+helper versus serial. Explicit `VITA3K_DIAG_JIT_PROFILE`, `VITA3K_DIAG_PVRTC_TELEMETRY` and valid `VITA3K_DIAG_PVRTC_THREADS=1/2` overrides take precedence over UI output/mode. JIT profiling observes compilation misses only and does not warm or replay guest code.
