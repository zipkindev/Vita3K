# Vita3K-Go .37 — recent texture demand and pipeline preparation preview

Windows x64 prerelease, optimized for testing on the Lenovo Legion Go. Based on
Vita3K and Vita3K-Plus, with selected Vita3K-nx changes and additional performance
and diagnostic work. Other devices and games require separate validation.

## Changes since the .27 binary preview

- More exact Vulkan pipeline recipes, earlier shader preparation, bounded dynamic
  scheduling and refreshed bindings for recreated programs. Previously unseen or
  protected draws can still compile synchronously; missing draws are not used as
  a sync-mode optimization.
- Graphics pipeline libraries disabled by default after loading/device-loss
  experiments. The stable monolithic path is retained; library opt-in remains
  experimental and is not part of this validation.
- Validated PVRTC cache hits copy directly into mapped Vulkan staging instead of
  materializing an intermediate pixel buffer. Staging waits occur outside the
  decoded-cache lock. Windows automatic preparation can issue bounded page hints;
  these do not pin memory or ensure residency.
- Automatic texture preparation learns bounded recent CPU demand and first-demand
  companion groups. Recent inputs, costly cold inputs and related entries compete
  within the existing 75% preparation ceiling; the rest remains available for
  demand. No game/track lists are hardcoded. Runtime replacement is unchanged.
- Version 2 learned profiles persist the new metadata. Version 1 imports remain
  supported. The existing cache/preparation UI controls the feature; diagnostics
  remain optional. No asynchronous texture prediction or race-loading detector.

## Validation and remaining limits

Final fresh-process Chenghou Project Rapier, four laps: Vulkan 2×, AF4, Bilinear,
VSync/shader cache on, high accuracy on, surface synchronization enabled,
external-host mapping, 512 MiB, two-way decoding, automatic preparation on,
async pipeline compilation **off**, diagnostic observers enabled.

The final 120-second recorder window had 3,598 wholly contained presentation
intervals: median **33.33 ms**, p99 **35.51 ms**, maximum **129.25 ms**, with **3 ≥50 ms**
and **1 ≥100 ms**. Some stutters and correct graphics were reported. Recording
followed a manual start-click; the exact first driving frame/phase boundaries were
not instrumented. A 2m17s race was reported. This is presentation cadence, not
controller-to-display latency or a controlled previous-version speedup.

All eight previously tracked costly texture inputs were prepared, used and needed
no demand decoding in the final session. Startup prepared 3,255 inputs in 2.79 s.
Whole-session counters include menus: 223 demand decodes, no byte/entry capacity
evictions, peak sampled resident payload about 416.67 MiB. Learned inputs, disk
caches and encounters differed from earlier versions, so no percentage gain is
claimed. A 129 ms gap still overlaps synchronous pipeline compilation, and a
65 ms gap overlaps texture decoding. The under-50/100-ms goals remain unmet.

**34/34 Windows tests passed.** Exact optimized EXE/PDB identities and live symbol
loading verified on the Go. Killzone Mercenary 1.12 reached rendered UI after
installing its existing license; gameplay and performance were not tested.

## Downloads and upgrade

- **Runtime ZIP:** optimized EXE and runtime dependencies.
- **Diagnostics ZIP:** matching PDB and build evidence; extract beside that runtime
  when profiling. It is the same optimized executable, not a separate Debug build.
- **SHA256SUMS / provenance:** verify downloads and EXE/PDB identity before analysis.

Keep a backup of the portable installation, saves, settings and learned profiles;
install separately for rollback. `.37` reads version 1 learning but saves version 2.
Older builds cannot read the new format: retain their original profile backups.
No games, licenses, saves, traces or learned payloads are included in the downloads.

Open **Settings → Texture Decoding** to select a decoded RAM budget and enable
**Automatic Texture Preparation**. Play and close normally to save learning; later
launches prepare compatible inputs. Unknown effects still require demand work.
Saved profiles remain capped at 64 MiB/game and 1 GiB total, with clear-profile
controls; older observations can be replaced at the bounds. Leave optional
observers off for routine play. See [setup](../windows-setup.md),
[symbol instructions](../windows-symbols.md), [findings](../performance-findings.md)
and [selection/storage details](../recent-demand-preparation-37.md).
