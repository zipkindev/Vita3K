# v1.3.3-win11merge.9 — Bounded session JIT profiling

The .8 learning run filled its initial chronological buffer before the recorded
race. This candidate continues observing main-thread compilation misses for the
whole session, while keeping memory and output bounded. Based on .8 / tested .6;
the separate .7 upstream-import candidate remains excluded.

- Rolling history of the latest 65,536 detailed compilations, exported in
  chronological sequence order. Sequence ranges, overwritten count and QPC
  coverage show exactly which details remain. Observation continues after wrap.
- At most 4,096 session time buckets, initially one second wide. Adjacent buckets
  merge and their width doubles when necessary. Counts, total/max inclusive
  compilation time, emitted bytes, aborts, invalidations and flags are preserved.
  Summaries cover idle time through shutdown; compile time belongs to the bucket
  in which compilation started, rather than being apportioned across boundaries.
- Lifetime totals remain separate from retained-detail totals. Long sessions
  lose time resolution as buckets merge; old detail can be overwritten. Check
  coverage before correlating a race, and close normally soon after recording.
- Schema 2: armed.json, compilations.csv, session.csv and summary.json. No
  compilation-path file I/O or allocation. Memory: 6 MiB detail payload plus
  256 KiB bucket payload, allocated before main guest execution.

Profiling remains diagnostic-launcher opt-in and main-thread/x64 only. No JIT
prewarming or guest execution simulation. Timings include observer overhead;
startup-region matches and bounded fingerprints do not authorize replay. No game
instruction bytes/native code images are persisted. Normal closure saves the
reports; a crash can leave only armed.json. Keep reports private.

Automatic Texture Preparation, preserved saves/graphics/controls and the 512 MiB
texture RAM trial are unchanged. Profiling storage is additional to texture RAM.
Runtime and matching-symbol diagnostics downloads use the same optimized build.

Validation includes ARM/Thumb execution equivalence, cache-hit exclusion,
invalidation re-observation, wrap ordering/continued observation, deterministic
multi-hour bucket folding with exact totals/maxima, and CSV/JSON consistency.
Dedicated Windows suite/build provenance and isolated Go checks accompany the
artifact. No performance improvement is claimed from the profiler itself.
