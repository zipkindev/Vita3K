# Pipeline telemetry diagnostic .19

Based directly on the exact `.17` allocator candidate (`84a7b7d81f843631e8243b2d87341b66db14dab4`). This build does not include `.18` invalid-code handling. It retains the colour-clamping and user-memory-budget corrections from `.16`, with their upstream credit, and all earlier Go texture-learning and diagnostic work from Vita3K, Vita3K-Plus and Vita3K-nx.

Adds **Vulkan Pipeline Telemetry** under Texture Decoding → Diagnostics (Optional). It is off by default, applies per game or globally, and requires restarting the game. It measures selected pipeline work, including async queue delay/compilation, skipped pending draws, protected-draw waits, synchronous compilation reasons, driver cache probes and existing background warm-up outcomes. It does not change pipeline compilation eligibility, worker counts, draw-skipping policy, cache budgets or scheduling.

Selected spans contribute bounded session summaries. A rolling buffer retains up to 65,536 completed spans lasting at least 2 ms, with 4 MiB record storage and 4,096 adaptive summary buckets (about 288 KiB). Records use the shared QPC clock, native thread IDs and session-local opaque pipeline/pair identifiers; no shader bytes, game assets or Vulkan handles are exported. Contention drops, overwritten records and in-flight work are reported. Ready pipeline hits are not instrumented. Queue and compile spans, and nested warm-up spans, overlap: totals are elapsed observations, not CPU/GPU time or additive frame cost. Cache-probe result zero means no pipeline returned, not necessarily an error.

Close normally to save `armed.json`, `summary.json`, `kinds.csv`, `session.csv` and `pipelines.csv` under the installation's `portable/cache/diagnostics/pipelines/` directory. Session summaries cover accepted observations, while detail has bounded recall; missing records cannot rule out stalls. Delete old diagnostic session folders when no longer needed. Diagnostic overhead must be checked before making small performance claims.

The release recipe produces one optimized RelWithDebInfo executable and a separate matching-symbol package. Verify source/EXE/PDB provenance and GUID/age before tracing. `.19` is an investigation build, not a performance fix; no gameplay speedup is claimed before validation.
