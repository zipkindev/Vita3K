# .21: bounded texture preparation coverage

Diagnostic candidate based on .20. Helps explain first-use decoding by distinguishing launch-profile misses, preparation budget/deadline skips, and prepared inputs decoded after eviction or clear. Adds session-local texture IDs, rolling slow-decode detail, learning eviction counts and successful saved-profile membership. Startup preparation reports get a separate immutable snapshot.

Enable Texture Cache Coverage Telemetry under Texture Decoding and close the game normally to save the coverage reports. Tracking is off by default, limited to 32,768 identities and 8,192 slow decodes, with explicit loss counters and less than 4 MiB coverage payload. Reports contain no texture bytes, hashes or guest addresses. See [report format and limitations](../decoded-texture-telemetry.md).

Texture decoding, learning admission, preload ordering, ordinary LRU and JIT preparation behavior remain as in .20. This adds diagnostic overhead; it is not a performance fix. The planned Legion Go validation uses WipEout 2048, Chenghou Project Rapier/four laps, 512 MiB and the latest learned profile. No gameplay result is claimed before testing. Runtime and exact matching PDB packages are separate products of the dedicated Windows runner build; consult each package's provenance manifest for source and symbol identity.
