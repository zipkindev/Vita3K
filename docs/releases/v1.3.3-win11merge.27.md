# Windows release candidate .27

Vita3K-Go Windows x64 release candidate, focused on Lenovo Legion Go performance. This publishes the exact optimized `.27` executable tested on the device; it is not a rebuild or an integration of the newer upstream commits.

## Improvements since .15

- More selective decoded-texture retention and admission at a fixed memory budget. Reused or costly textures receive preference, and new admissions are evaluated before evicting valuable resident data. Bounded aging and repeated-demand admission allow the cache to adapt as games and scenes change.
- Automatic per-game texture learning, bounded profile merging and preparation before guest startup, with controls under **Settings → Texture Decoding**. Profiles are learned locally: no game-specific texture lists or game assets are supplied.
- Optional bounded diagnostics for texture coverage, eviction/admission/reuse, CPU copy/upload work, JIT compilation/startup, synchronization waits and Vulkan pipelines. These controls are independent of installing symbols and default off.
- Opt-in bounded, validated main-thread JIT preparation prototype. It is experimental, does not replay guest gameplay and is not required for texture caching. Leave it off for ordinary testing unless specifically comparing it.
- Reviewed vertex-color clamping, guest allocation-budget enforcement and bitmap allocator improvements, building on the existing Plus-derived scheduler and renderer.

## What we tested

Primary validation is WipEout 2048 on Windows 11 / Legion Go, including Chenghou Project Rapier four-lap races, traffic and weapons, plus a full Rapier tournament through Anulpha, Chenghou, Sebenco and Sol 2. The decoded-texture budget was **512 MiB**, with Vulkan 2× rendering and async pipeline compilation. Repeated tests were reported smoother and more consistent as learning/retention improved. The tournament was mostly smooth, with slight initial stutters that settled and one reported major quake-related hitch.

The tournament exercised the full 512 MiB cache. After the recorded start confirmation, pressure admission rejected 3,905 insertions and only two preloaded entries were evicted. These are diagnostic event counts, not a controlled speedup or a guarantee for other workloads. Loading/results are included in the continuous capture, so its whole-session frame statistics are not presented as racing-only performance.

Native analysis still identifies both texture decoding/uploads and protected Vulkan pipeline compilation/waits in larger gaps. The exact quake cannot be mapped to a specific gap from the available markers. This candidate reduces repeated work; it does not eliminate every first-use or heavy-effect hitch.

Earlier DOA5 Plus testing with async compilation at 2× was reported smooth with correct graphics; this is limited compatibility evidence from earlier builds, not a new `.27` validation of every game. Other games, Steam Deck and ROG handhelds need independent testing. General policy is dynamic per game, but new textures need an initial encounter and a learned profile may exceed the preparation/RAM budget.

## Measured comparisons and tested settings

| Test | Recorded result |
|---|---|
| Ubermall, cache Off → 256 MiB, sequential 45-second captures | Intervals above 50 ms: 10 → 1; maximum interval: 242.36 → 63.84 ms. |
| Chenghou Rapier, learned preparation Off → On, earlier 90-second pair | Intervals above 50 ms: 6 → 0; maximum interval: 161.75 → 36.62 ms. |
| DOA5 Plus `.11`, 1× synchronous → async pipelines | Intervals above 50 ms: 7 → 0; maximum interval: 298.20 → 36.35 ms. A later 2× async run had no intervals above 50 ms, maximum 45.39 ms. |

These are sequential workload-specific presentation measurements, not input-latency measurements or a guaranteed percentage speedup. Cache warming, opponents/effects, run order and unknown exact DOA stages limit causal attribution. The `.27` tournament has no controlled old-build tournament counterpart.

The latest WipEout configuration was Vulkan, **2× resolution, 4× anisotropic filtering, Bilinear screen filtering, VSync on, shader cache on, async pipeline compilation on, surface synchronization enabled, external-host mapping, accurate scheduling with three guest cores, 512 MiB decoded cache, automatic preparation and two-way parallel decoding**. Optional diagnostics and experimental JIT preparation were enabled for the investigation, so its observations are not a measurement with every diagnostic switched off. DOA5 testing used Vulkan, 1× anisotropic filtering, external-host mapping and a 512 MiB decoded cache; resolution changed from 1× to 2× with async enabled.

**Menu guide:** Texture Decoding contains the decoded RAM budget, Parallel Texture Decoding, Automatic Texture Preparation, profile-clear controls and optional diagnostics. Diagnostics measure behavior and add overhead; they are not speed switches. CPU contains Asynchronous Pipeline Compilation and the separate experimental main-thread JIT preparation toggle. Graphics contains shader caching and texture import/export. Texture import/export is unrelated to learned decoded-cache performance. Successful testing does not establish benefits for every game; experimental labels remain in this build.

## Downloads and setup

- **Runtime ZIP**: the optimized executable and required application libraries. Extract the entire ZIP into a separate folder; preserve your working installation and saves.
- **Diagnostics ZIP**: the matching full `Vita3K.pdb`, tests and build/dependency evidence. Optional; extract beside the runtime for profiling/debugging. This uses the same optimized executable, not an unoptimized Debug build.
- **downloads.json / SHA256SUMS**: archive hashes and exact source/build/native symbol identity.

Follow [Windows setup and dependencies](https://github.com/zipkindev/Vita3K-Go/blob/0c181b9e4badd538919809a83b3da0816e6380c4/docs/windows-setup.md) and [matching-symbol instructions](https://github.com/zipkindev/Vita3K-Go/blob/0c181b9e4badd538919809a83b3da0816e6380c4/docs/windows-symbols.md). Install the supported Microsoft Visual C++ x64 redistributable and a suitable GPU driver. LibAtrac9 is compiled into this build: players do not need a separate ATRAC9 DLL or codec download. Firmware, fonts, games, saves and learned texture/JIT profiles are not included.

For a texture-cache comparison, set the per-game decoded cache to 512 MiB, enable Automatic Texture Preparation, play a learning session and close normally to save it. Relaunch for the fresh-process comparison, retaining the same graphics and shader caches. Optional JIT preparation and telemetry are separate settings. Learn/prepare is not a guarantee that a particular upcoming map is completely resident.
