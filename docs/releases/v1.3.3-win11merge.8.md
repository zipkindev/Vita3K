# v1.3.3-win11merge.8 — Main-thread JIT profiling

Diagnostic learning candidate based on tested automatic-texture .6, preserving
.7 as a separate upstream-import experiment. No code is precompiled or guest
execution simulated. Default profiling is off; diagnostic launcher opts in.

## Added

- Optional x64 Dynarmic observer at actual compilation misses, excluding cache
  hits. Full location descriptors, raw QPC start/end, inclusive compilation time,
  emitted block bytes, invalidation epochs and bounded code-read fingerprints.
- Main guest thread only; startup module/segment snapshot and relative offsets.
  Region matches are address observations, not proof of current module identity
  after unload/reload or relocation. Read fingerprints are diagnostic and cannot
  authorize replay. Extra Mono translation-hook reads are observed separately.
- Fixed 65,536 chronological records (5.5 MiB record payload), at most 4,096 read
  words per record. Allocation/header output before the main thread starts;
  CSV/summary written after guest shutdown. No report file writes on compilation
  or frame paths. Saturation is flagged; a crash may leave only the armed header.
- Source-pinned, checksummed Dynarmic dependency patch and explicit diff evidence
  alongside exact optimized EXE/PDB/dependency/toolchain provenance.

## Usage and limits

Set VITA3K_DIAG_JIT_PROFILE to a fresh existing-parent output directory path before
launch. The directory itself must not exist. This feature has no UI setting yet.
Close normally after the learning run to save compilations.csv and summary.json;
armed.json records configuration/startup regions and the clock before execution.
Disable the environment variable for a same-executable profiling-off comparison.

Automatic Texture Preparation, its separate saved-profile storage and the 512 MiB
trial RAM budget remain as in .6. Profiling memory is additional to texture RAM.
Reports contain numeric guest addresses/fingerprints and module paths, not guest
instruction bytes or reusable native code. Keep reports local/private.

Timings include observer overhead; measure off/on before performance conclusions.
Only the first bounded chronological compilation events are retained. Secondary
guest threads and non-x64 backends are outside this observer's scope. Changed or
dynamically generated code may not be available during loading; this learning
run determines where a future compile-only preparation experiment could apply.

## Validation

Synthetic ARM/Thumb execution compares profiling on/off registers, memory writes
and SVC behavior; repeats verify no events on cache hits and re-observation after
invalidation. Bounds, flags, duplicate output refusal and CSV/JSON are checked.
Windows full-suite, exact live symbols and Go learning-run validation accompany
the built artifact; do not infer runtime proof from source review alone. No JIT
prewarming, speculation, extra decoder threads or OS tuning are introduced.
