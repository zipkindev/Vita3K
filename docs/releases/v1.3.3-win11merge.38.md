# Vita3K-Go .38 — Vulkan queue synchronization candidate

Private test candidate; gameplay validation pending. Based on .37 with unchanged
texture preparation, runtime cache policy and pipeline compilation settings.

Adapted from Vita3K mainline commit
[b89272d3de01c142aa4177f4e062c203fcb97962](https://github.com/Vita3K/Vita3K/commit/b89272d3de01c142aa4177f4e062c203fcb97962)
by Zangetsu38, with upstream co-author credit to Copilot.

A shared mutex serializes host submissions, presentation and queue/device-idle
operations. The port also covers additional Go/Plus surface-transfer, readback
and overlay initialization paths. Swapchain-image semaphore indexing was already
correct in .37 and remains unchanged. Fence waits and callback dispatch stay
outside the queue lock; single-time helpers contain their own queue-idle calls
and therefore execute under it. Existing command-pool lifecycle rules remain.

This corrects missing Vulkan external synchronization. No pipeline compile-time
or frame-time improvement is claimed; additional serialization may affect timing.
The first checks are menu/launch/close stability followed by one short matched
Chenghou Rapier comparison at 512 MiB with async compilation off. Preserve the
same learned texture, JIT and pipeline inputs for both sides. A tournament is
unnecessary for the initial check.

The optimized Windows build is paired with its exact PDB. Build provenance records
the source commit, support/dependency patches, compiler, configuration, hashes and
PE/PDB identity. Keep .37 and the production installation intact.
