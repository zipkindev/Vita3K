# Vita3K-Go .38 — Vulkan queue synchronization preview

**Windows x64 prerelease.** Unofficial Vita3K/Plus-derived fork focused on Lenovo
Legion Go testing, with selected Vita3K-nx work and additional automatic texture
learning, pipeline preparation and optional diagnostics. Other devices and games
require separate validation. This is not a stable release or a full mainline merge.

## Changes since .37

Adapted mainline [b89272d3](https://github.com/Vita3K/Vita3K/commit/b89272d3de01c142aa4177f4e062c203fcb97962),
by Zangetsu38 (upstream co-author Copilot), to synchronize host access to shared
Vulkan queues. The port also covers Go/Plus surface transfers, readback, overlay
initialization and device-idle operations. Submit/present use the same mutex;
explicit fence waits and callback dispatch remain outside it. Swapchain-image
semaphore indexing was already correct in .37 and remains unchanged.

This fixes missing Vulkan external synchronization. Additional serialization can
affect timing; a pipeline compilation speedup is not claimed. Texture selection,
cache replacement, pipeline scheduling and async defaults are unchanged from .37.
All existing .37 features remain: bounded automatic per-game learning, recent
texture demand and companion selection, parallel PVRTC decoding, direct cached
pixel staging, exact pipeline recipes and optional diagnostic reports. See
[.37 feature notes](v1.3.3-win11merge.37.md) and
[performance findings](../performance-findings.md).

## Testing and limits

Native local Windows MSVC **34/34 tests passed**, plus 140 package payload hashes,
exact optimized EXE/PDB identity, live private symbols, intro/menu input and normal
closure verified on the Go. Gameplay used a fresh process with the latest closed
.37 learned texture/JIT/exact-pipeline/driver caches, **512 MiB**, Vulkan **2×**,
AF **4×**, Bilinear, VSync/shader cache on, high accuracy on, surface synchronization,
external-host mapping, automatic preparation/two-way decoding and **async pipeline
compilation off**. Optional diagnostic observers were enabled.

Chenghou Project, Rapier, four laps: recording began before the remote final-start
click and stopped 120.072 seconds later. The window includes countdown/loading;
exact race/death phase boundaries are not instrumented. A death was reported
around the end, so this is **not a confirmed uninterrupted 120-second race**.
Feedback reported no noticeable stutters from a cold process start.

| Presentation intervals wholly inside the recorder window | Result |
|---|---:|
| Samples | 3,601 |
| Median | 33.3432 ms |
| p99 / p99.9 | 35.2757 / 36.4560 ms |
| Maximum | 60.8090 ms |
| Intervals ≥50 / ≥100 ms | 2 / 0 |

The two ≥50 ms intervals ended at start-input +9.05 s and +119.91 s; their phase
and cause remain unconfirmed. These are presentation intervals, **not input
latency**. The previous .37 capture had a 129.25 ms maximum, but profiles, effects
and capture protocols differed. No causal or percentage speedup claim follows.
The goal of every gameplay interval below 50 ms is not established.

The process loaded 191 exact recipes, prepared 27 and reused 18 across the whole
session. The particular recipe associated with .37's 106 ms stall was queued and
prepared in .38; its coverage flags do **not** show exact-object reuse in this
race. A prepared pipeline is not automatically proof of demand coverage.

Vulkan validation was **off** during performance measurement. The Go currently
has no registered Khronos validation layer. No validation-enabled Vulkan
correctness pass is claimed. Separate correctness/performance lanes with restored
input snapshots and explicit layer activation checks are being prepared. A
startup watchdog warning overlapped shader precompilation in both .37 and .38;
normal intro/menu progression followed. Gameplay reports are not an exhaustive
compatibility or race-condition test.

## Downloads and setup

- **Runtime ZIP:** optimized Windows EXE and dependencies.
- **Diagnostics ZIP:** the exact matching PDB and build evidence. Extract beside
  that runtime when profiling; it is the same optimized EXE, not a Debug build.
- **SHA256SUMS / provenance:** verify downloads and matching GUID **and age**.

Install separately and retain a rollback copy of saves, settings and learned
profiles. Settings → **Texture Decoding** controls decoded RAM and **Automatic
Texture Preparation**. Play and close normally to save learning; later launches
prepare known compatible inputs. Unknown effects still need demand work. Profiles
remain capped at 64 MiB/game and 1 GiB total. Version 2 profiles are readable by
this preview; older builds require their original profile backups.

See [dependencies/setup](../windows-setup.md), [symbol instructions](../windows-symbols.md),
[feature controls](../../README.md#menu-controls-and-expected-effects) and
[storage/selection limits](../recent-demand-preparation-37.md). No games, licenses,
saves, raw traces or learned texture payloads are included. Original Vita3K,
Plus and nx authorship and licenses remain credited.
