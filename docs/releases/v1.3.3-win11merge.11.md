# v1.3.3-win11merge.11 — Bounded texture reuse telemetry

Based on `.10`, this diagnostic candidate distinguishes textures decoded after a tracked capacity eviction from first-observed textures, explicit clears and other known misses. It also reports elapsed decode time by miss category and bounded preload-hit counters. This helps decide whether remaining first-lap hitches need broader preparation or better cache retention.

The existing **Settings → Performance → Texture Cache and Reuse Telemetry** switch controls the feature, globally or per game. Default off. Schema 2 appends counters to the existing one-second CSV. Fixed 65,536-slot fingerprint history uses up to 4 MiB extra memory; replacements and epochs expose incomplete recall. No texture bytes or fingerprints are exported. First-observed does not mean first-ever, and 64-bit fingerprint collisions can affect diagnostics only. Actual cache hits still verify compressed bytes.

The 512 MiB trial retains `.10` cache admission/eviction, automatic preparation, parallel worker count, JIT observer and synchronization telemetry. No scheduler, graphics or decoding policy change and no performance improvement claimed. The separate `.7` upstream candidate remains excluded. See [reuse telemetry](../texture-reuse-telemetry.md) for classification and correlation limits.

Runtime and matching-symbol downloads share one optimized executable; diagnostics adds the exact PDB and provenance. Dedicated Windows server build and isolated Go staging must be verified before gameplay conclusions. Raw reports and game-derived learned profiles are not distributed.
