# .36: direct decoded-cache staging and bounded Windows page hints

The .35 Chenghou traffic trace showed Windows compressed-memory restoration beneath decoded-cache copies. A decoded cache hit can therefore still fault while reading pixels; replacing texture decoding alone does not eliminate all first reads.

The Vulkan PVRTC hit path now consumes validated immutable pixels directly into mapped staging. A CPU-only consumer runs under cache protection so eviction cannot invalidate its span. Staging allocation and fence waits happen before reacquiring the cache; Vulkan commands run after release. No pointer escapes to GPU commands. Cache misses, exported textures and other backends retain the existing decode/scratch path. Probe misses do not invent extra request/miss observations.

Automatic Texture Preparation additionally enables a Windows PrefetchVirtualMemory hint for eligible cached payloads, before staging preparation. Requests are bounded to 256 KiB–8 MiB each and 64 MiB per second per renderer thread. Missing APIs or failed hints retain normal behavior. This is an on-demand preparation hint, not an asynchronous decoder, residency guarantee, memory pin, periodic full-cache scan or loading-screen detector. The OS call's runtime is measured but cannot be forcibly time-limited. It may itself have a cost and requires measurement. `VITA3K_DIAG_TEXTURE_PREFETCH=0` disables hints for diagnostic comparison without disabling direct staging. No system memory-compression setting changes.

CacheDirectUpload (kind 15) records the hit attempt, result 0 on success and 1 on fallback. CachePrefetch (kind 16) records the Windows request/result. CacheResidency (kind 17) samples at most 64 pages before a rate-eligible request: result is the sampled nonresident-page count, or -1 on query failure. Samples do not distinguish cached source versus scratch faults in the earlier trace; .36 avoids scratch materialization on successful hits. Existing staging-copy spans now include the direct transfer, while CachePixelCopy remains exclusive to the old scratch route. Nested span durations must not be summed.

The byte budget and learned profile format remain unchanged. Tests cover byte-identical PVRTC I/II in both bit depths, changed-content rejection, neutral misses, failed staging preparation, revalidation after clear, concurrent clear/eviction during a CPU consumer and cache budget accounting. Performance gains and visual correctness remain pending handheld validation at 512 MiB with async pipeline compilation off. Keep .35 for rollback and freeze the same learned inputs before comparing.
