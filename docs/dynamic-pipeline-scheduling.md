# Dynamic Vulkan pipeline preparation candidate (.31)

Exact learned recipes take priority over guessed shader pairs. Finishing a job retries recipes deferred by the bounded queue, even without another program-registration callback. Duplicate registration callbacks do not rescan unchanged registries. Consumed ready objects release preparation capacity while the renderer keeps ownership; completed work transfers directly into its pipeline map.

Recent draw activity limits preparation to one running job; after 250 ms without draws, up to two jobs may run. Activity is sampled every 64 draws, including ready hits. A miss or in-flight draw wait holds an explicit activity marker, so long rendering stalls cannot be misclassified as idle time. Already running work is not cancelled. Windows preparation workers use below-normal thread priority; when a draw must wait for an exact job already running, its worker is promoted to normal priority until the job finishes. Guest scheduling, process priority and affinity are unchanged. No critical/high/realtime priority or core pinning is introduced.

Recipe matching canonicalizes state ignored by pipeline construction: region clipping, unused back-face state and texture units the shader does not use. Used texture formats, shader identities, layout, blending, casts, gamma, attachment/output formats and relevant depth/stencil state remain distinct. Existing schema1 .30 profiles remain readable. Raw fragment-input hints are derived from the actual compile conditions. Matching is not reduced to the pipeline hash alone.

Bounds remain 64 pending jobs, 256 queued/running/ready exact objects, 1,024 recipe entries, 2,048 registered program bindings and eight bindings per program. Taken/failed jobs retain bounded metadata but do not consume object capacity. Shutdown wakes workers, joins running work and disposes queued requests without leaving sentinel jobs. `[PIPESCHED]` reports exact misses, waits and scheduled jobs; existing reason0x30 detail identifies exact compilation and required waits.

This is background preparation independently of the asynchronous draw-compilation checkbox. With async off, an unseen or unfinished required pipeline can still stall. No draw is skipped by these changes. No performance improvement is claimed before validation. Testing uses .30's learned recipes, 512 MiB decoded textures and async off; no new texture policy or upstream imports are included.
